## 0. Atmos Bridge Host (v2.0)

```
플레이어 → CABLE In (VB-Audio) → [Atmos Bridge Host: 직접 루프백 → 라우팅 → 플러그인 체인]
  → Atmos 7.1.4:  Windows 공간 음향 (Dolby Atmos for home theater, MAT) → AVR
  → 2ch Stereo:   WASAPI Exclusive 모드 PCM 2.0 → AVR 업믹서 (Dolby Surround · Auro-3D · Neural:X)
```

**설치**
- **Install 버전**: `...-Install-win64.exe`를 실행합니다. `C:\Program Files\Atmos Bridge Host`에 설치되고 **시작 메뉴** 바로가기가 생깁니다. **바탕화면 바로가기**와 **VST3 플러그인 함께 설치**는 설치 화면에서 고릅니다. 새 버전도 같은 방법으로 덮어 설치하면 됩니다(실행 중이면 닫고 설치, 설정은 그대로). 제거: **설정 > 앱 > 설치된 앱 > Atmos Bridge Host**.
- **Portable 버전**: zip을 풀어 아무 폴더(예: `C:\Atmos Bridge Host`)에 두고 `Atmos Bridge Host.exe`를 실행합니다.
- 두 버전은 같은 설정(`%APPDATA%\Atmos Bridge Host`)을 씁니다. 서명되지 않은 프로그램이라 처음 실행할 때 SmartScreen 경고가 뜨면 **추가 정보 → 실행**.
MultiChannel Plugin Host는 **끄세요**(같은 AVR을 두 프로그램이 쓰면 2ch Exclusive 모드가 열리지 않고, 두 번 출력될 수 있습니다).

**화면** — 플러그인과 같은 스피커 배치 · 채널 매핑(번호표) · 테마에 호스트 기능이 더해졌습니다.

| 위치 | 기능 |
|---|---|
| 상단 | 상태 · **출력 형식 [2ch Stereo \| Atmos 7.1.4]** · 모드 [기본 \| 저지연] |
| INPUT | **재생 장치**(자동 = CABLE In 16ch, 없으면 CABLE Input): 플레이어가 그 장치로 내보내는 소리를 직접 받음(루프백, 가장 빠름) · **녹음 장치**(CABLE Output 등): 일반 녹음 입력, VB-Cable 내부 버퍼만큼 늦음. 입력이 44.1 kHz 등이면 그 레이트로 처리 |
| ENGINE | 48000 Hz · **Buffer** (2ch: 128 / 256 / 480 / 512 / 1024 samples = 2.7 / 5.3 / 10 / 10.7 / 21.3 ms, 기본 480 · Atmos: 10 ms 고정) · **Exclusive** (2ch: 눌러서 켜기/끄기, 기본 켬 · Atmos: 사용 불가) |
| OUTPUT | AVR (자동 = AVR/HDMI 우선) |
| ROUTING | 입력 16채널 → 처리 12채널 매트릭스, 입력별 레벨 · 뮤트, 두 번째 탭은 번호표(처리 → 스피커) |
| ⤓ | 트레이로 숨기기 |
| 플러그인 체인 | 스테레오 플러그인(최대 4)과 업믹서(최대 4)를 **한 목록**에 넣고 ≡ 를 끌어 순서 변경 |
| 아래 | 순차 테스트 톤 · 지연(입력 + 여유 + 플러그인 + 출력) · 끊김 · **MASTER** 볼륨 · MUTE · 동작 상태 |

**플러그인 체인**
- **+ 플러그인 추가** → "스테레오 플러그인 (2 → 2)" 또는 "업믹서 (2 → 12ch)"에서 고릅니다. 추가하면 설정 창이 열리고, 이름을 누르면 다시 열립니다.
- 위에서부터 순서대로 처리합니다. **업믹서 앞은 2채널(CH 1-2), 뒤는 12채널**이고, 업믹서 뒤에 둔 스테레오 플러그인은 CH 1-2(L/R)에 적용됩니다.
- 스테레오 플러그인마다 **[2ch · Atmos / 2ch만 / Atmos만]** — zBACCH 같은 XTC는 "2ch만"으로 두면 Atmos에서 자동으로 쉽니다.
- 모든 줄에 **O/X**(켜기 · 끄기, 켜진 업믹서는 하나) · **B**(바이패스) · **D**(삭제). 업믹서는 2ch Stereo에서 쉽니다(업믹스는 AVR이).
- 체인과 각 플러그인의 설정, 라우팅, 번호표, 출력 형식, 모드, 볼륨은 바뀔 때마다 자동 저장되어 다음 실행 때 그대로 열립니다
  (`%APPDATA%\Atmos Bridge Host\host-state.dat`).

**2ch Stereo**
- PCM 2.0(48 kHz 24-bit 우선)을 **Exclusive 모드**로 AVR에 보냅니다. Windows 믹서와 공간 음향을 거치지 않으므로 AVR이 PCM을 받고 업믹서를 쓸 수 있습니다.
- AVR 장치 속성 → 고급 → **"응용 프로그램이 이 장치를 단독으로 제어하도록 허용"**이 켜져 있어야 합니다 (꺼져 있으면 상태에 "Exclusive 모드 꺼짐").
- 출력하는 동안 다른 앱(알림음 등)은 AVR로 소리를 낼 수 없습니다. 다른 앱이 AVR을 쓰고 있으면 상태에 "AVR을 다른 앱이 사용 중".
- **Exclusive를 끄면(공유 모드)** Windows 믹서를 거쳐 나가서 다른 앱 소리도 AVR로 함께 나옵니다. 대신 지연이 늘고(Windows 버퍼, 보통 20 ms 안팎) Buffer 선택은 쓰지 않습니다. Windows 공간 음향(Dolby Atmos for home theater)이 켜져 있으면 2ch도 Atmos 신호로 나가므로 AVR 업믹서를 쓸 수 없습니다. 이때는 소리 설정에서 공간 음향을 끄세요(Atmos 7.1.4로 돌아가면 자동으로 다시 켜 봅니다).
- Buffer를 줄이면 지연이 줄지만 끊김 위험이 커집니다 (AVR 드라이버의 최소 주기보다 작게는 열리지 않습니다). 기본 480 samples(10 ms)에서 시작해 끊김이 없으면 256 · 128로 줄여 보세요.
- XTC(zBACCH 등)를 쓸 때는 AVR을 **Stereo**(또는 Direct) 모드로 두세요.

**Atmos 7.1.4**
- 지금까지와 같은 공간 음향 출력입니다. AVR에 공간 음향이 꺼져 있으면 **"Dolby Atmos for home theater"를 자동으로 켜 봅니다**(Windows가 거부하면 소리 설정에서 직접 선택).

**모드** — Host는 **기본 · 저지연** 두 가지입니다(둘 다 직접 루프백, 호스트 입력이 없으므로). 기본 = 여유 20 ms 이상(가장 안정적), 저지연 = 자동 보정. 처음 실행은 **저지연**.
초저지연+는 Host에서 뺐습니다: VB-Cable에서는 짧은 입력 주기를 쓸 수 없어 저지연과 차이가 몇 ms뿐이었습니다(예전 설정은 저지연으로 열림). VST3 플러그인에는 그대로 있습니다.

**트레이**
- ⤓ 버튼, 최소화, 닫기(X)로 트레이에 숨습니다. **소리는 계속 나갑니다.** 아이콘 클릭 = 창 열기.
- 아이콘 점 색: 초록 출력 중 · 노랑 연결 중/BYPASS · 빨강 오류 · 회색 정지/MUTE. 마우스를 올리면 형식과 지연.
- 오른쪽 클릭 메뉴: 창 열기 · 출력 형식 · 모드 · BYPASS · MUTE · **최소화하면 트레이로 / 닫기(X)도 트레이로 / Windows 시작 시 트레이로 자동 실행** · **종료**.
  처음에는 최소화·닫기 → 트레이가 켜져 있고, 자동 실행은 꺼져 있습니다. 프로그램을 끝내려면 트레이 메뉴의 **종료**.
- 한 번만 실행됩니다 (다시 실행하면 열려 있는 창이 앞으로 나옵니다).

**소리가 두 번(겹쳐) 들릴 때** — 같은 AVR로 소리를 내는 다른 프로그램이 있으면 상태 표시가 주황색 **"다른 앱도 AVR로 출력 중: (프로그램 이름)"**으로 알려 줍니다.
흔한 경우: MultiChannel Plugin Host(+ Atmos Bridge 플러그인)가 아직 켜져 있음 · 플레이어가 CABLE이 아니라 AVR로도 출력 · CABLE Output의 "이 장치로 듣기"가 켜져 있음.
확인: Atmos Bridge Host의 **MUTE**를 눌러도 소리가 나면 다른 경로가 있는 것입니다. 체인의 RoomSpace 같은 공간 효과 플러그인도 겹쳐 들리는 느낌을 줄 수 있으니 **B**로 비교해 보세요.

**로그** — `다운로드\AtmosBridge\Logs\atmosbridge-host.log`

## VST3 플러그인

업믹서가 만든 **12채널(7.1.4)** 신호를 Windows 공간 음향 API(**ISpatialAudioClient**)로 넘겨,
Windows의 **Dolby Atmos for home theater** 인코더가 **Dolby MAT**로 HDMI → TV eARC → AV 리시버에 보내도록 하는 **VST3 플러그인**입니다.
HDMI LPCM의 8채널 한계를 넘어 7.1.4 12채널을 리시버가 Dolby Atmos로 받습니다.

```
음악/영상 플레이어 → CABLE In 16ch (VB-Audio) → MultiChannel Plugin Host (루프백 입력)
  → zSonic Upmixer (12ch) → [Atmos Bridge 7.1.4ch]
  → Windows 공간 음향 (고정 객체 12개, 7.1.4) → Dolby Atmos for home theater 인코딩 (MAT)
  → HDMI → TV eARC → Denon AVR-X3800H (Dirac Live ART) → 12개 스피커
```

> Windows 10/11 x64 전용 · 48 kHz 기준 · 개인 사용 목적

## 1. 다운로드와 설치

1. 이 저장소의 **Releases**에서 `Atmos-Bridge-7.1.4ch-v<버전>-VST3-win64.zip`(VST3 버전)을 내려받습니다.
2. 압축을 풀고 `Atmos Bridge 7.1.4ch.vst3` **폴더 전체**를 `C:\Program Files\Common Files\VST3`에 복사합니다.
3. 호스트에서 **Rescan**을 눌러 플러그인 목록을 새로 고칩니다.

## 2. Windows 설정 (처음 한 번)

| 장치 | 설정 |
|---|---|
| **AVR_x3800h (AMD High Definition Audio Device)** | 속성 → 고급: 기본 형식 **48000 Hz** · 공간 음향: **Dolby Atmos for home theater** (Dolby Access 필요) |
| **CABLE In 16ch (VB-Audio)** | 기본 형식 **48000 Hz** · 음악/영상 플레이어의 출력 장치(또는 Windows 기본 재생 장치)로 지정 |

AV 리시버는 스피커 구성 7.1.4와 Dirac Live ART 보정을 그대로 둡니다. 보정은 리시버가 Atmos를 디코딩한 뒤 적용되므로 그대로 유지됩니다.

## 3. 호스트(MultiChannel Plugin Host) 설정

| 항목 | 설정 |
|---|---|
| Input | CABLE In 16ch (VB-Audio Virtual Cable) [Loopback] |
| Output | AVR_x3800h (AMD High Definition Audio Device) (2) |
| Sample Rate | 48000 Hz |
| **Exclusive** | **해제 (필수)** — 독점 모드에서는 공간 음향 스트림이 열리지 않습니다 |
| 플러그인 체인 | zSonic Upmixer → **Atmos Bridge 7.1.4ch (맨 끝)** · 또는 **Atmos Bridge 하나만** 두고 내장 업믹서 슬롯 사용(아래 5-1) |
| Open Auro-3D Encoder | **체인에서 제거** (Atmos 경로에는 필요 없음, 약 1.1초 지연의 원인) |

- 플러그인은 호스트 쪽 출력으로 **무음**을 돌려줍니다. 소리는 Windows 공간 음향으로만 나가므로 두 번 들리지 않습니다.
  호스트 출력(AVR, 공유 모드)은 **클럭 기준** 역할을 하며, 이렇게 해야 호스트와 Atmos 출력이 같은 클럭으로 돌아 드리프트가 생기지 않습니다.
- 플러그인 상단의 출력 장치는 **자동**이면 공간 음향이 켜진 AVR/HDMI 장치를 스스로 찾습니다(가상 케이블은 제외). 확실히 하려면 목록에서 AVR을 직접 고르세요.
- **출력 장치를 VB-Cable 같은 가상 케이블로 두면 안 됩니다.** 호스트가 그 케이블에서 소리를 받아오므로, 출력이 다시 입력으로 들어가는 피드백이 생기고(레벨이 최대로 치솟음) AVR에서는 소리가 나지 않습니다. 이때 상태 표시가 주황색으로 경고합니다.
- 플러그인은 한 번에 **하나의 인스턴스**만 출력합니다(두 번째 인스턴스는 비활성으로 표시).

## 4. 처음 켰을 때 확인 순서

1. 플러그인 창 상단 상태가 **초록색 "출력 중 · AVR_x3800h…"**인지 확인합니다.
2. 음악을 재생하고 AVR 화면(입력 신호 정보)에 **Dolby Atmos**가 표시되는지 확인합니다.
3. 아래쪽 **순차 테스트 톤**을 눌러 12개 위치가 2초씩 차례로 울리는지, 화면에서 빛나는 스피커와 실제 스피커가 같은지 확인합니다.
4. 채널 표의 **노이즈 버튼(파형 아이콘)**으로 Ch 1~12가 각각 의도한 위치로 나가는지 확인합니다.
5. 호스트 프로젝트를 저장했다가 다시 열어 매핑·뮤트·모드·업믹서 슬롯이 복원되는지 확인합니다.

## 5. 화면과 기능

**상단** — 테마 선택 · 출력 장치 선택(자동/장치 목록) · 상태(출력 중/연결 중/공간 음향 꺼짐/오류, 마우스를 올리면 자세히) · 출력 샘플레이트 · 모드(**기본/저지연/초저지연+**)

**왼쪽: 7.1.4 스피커 배치** — 각 스피커가 소리에 맞춰 **네온**으로 빛나고, 클리핑에 가까우면 경고색으로 바뀝니다(v1.4 다이나믹 네온).
- 조용한 채널은 어둡고 큰 채널은 밝게(대비를 키운 밝기), 소리가 줄면 빠르게 어두워집니다.
- 드럼·강세처럼 **갑자기 커지는 순간**에 번쩍이고(Cyberpunk는 가운데가 흰빛으로 달아오름), 부드러운 빛이 스피커에서 바깥으로 **퍼져 나갑니다**(스프레드, 0.85초).
- 천장 4개의 빛줄기는 타격 때 넓어지고, 바닥 스피커 아래에는 빛이 번집니다.
- 스피커 배치만 초당 60번 그리고(나머지 화면은 30번), 아무 소리도 없을 때는 다시 그리지 않습니다. 그리기가 느린 PC에서는 자동으로 30번으로 낮춥니다.
스피커 안의 숫자는 그 위치로 들어가는 **입력 채널 번호**, 아래는 위치 이름입니다. 스피커를 **클릭**하면 그 위치로 핑크 노이즈가 나갑니다.

**가운데: 채널 매핑**

| 항목 | 기능 |
|---|---|
| 입력 | Ch 1~12 = 호스트 채널 1~12(업믹서가 켜져 있으면 업믹서 출력). 기본 순서 **L, R, C, LFE, SBL, SBR, SL, SR, TFL, TFR, TRL, TRR** |
| 번호 | 출력 위치 번호 (1=L 2=R 3=C 4=LFE 5=SBL 6=SBR 7=SL 8=SR 9=TFL 10=TFR 11=TRL 12=TRR, **0=끄기**). 같은 번호를 두 번 넣으면 경고 후 합산 |
| 출력 위치 | 지정된 위치 이름 (L, R, C …) |
| 노이즈 | 그 입력 채널로 핑크 노이즈 (매핑·뮤트가 그대로 적용됨) |
| 뮤트 | 채널별 **M** · 위쪽 **All Mute / All Unmute** · **기본값**(지금 번호표를 1~12로 되돌림) |
| 레벨 | 입력 레벨 미터와 dB |
| 적용된 업믹서 | 지금 켜진 업믹서(없으면 "업믹서 없음"). 화면의 번호표는 이 업믹서의 것입니다 |

**오른쪽: 클리핑 방지 · BYPASS · 업믹서**

- **클리핑 방지 (켜짐/꺼짐)**: -1.0 dBFS를 넘지 않도록 **12채널을 같은 비율로** 줄입니다(스피커 사이 균형 유지). 미리 보기(look-ahead)가 없어 **지연은 0 ms**이고, -1.0 dBFS 아래 신호는 전혀 건드리지 않습니다. 기본값은 켜짐.
- **BYPASS (Atmos Bridge 7.1.4ch 전체)**: 켜면 원본 신호를 **손대지 않고 호스트 출력으로 그대로** 보내고, Atmos 출력은 무음이 됩니다(Atmos 스트림은 열린 채 유지되어 끄면 바로 돌아옴). 원본과 Atmos 업믹스를 비교해 들을 때 씁니다.
  - 켜고 끌 때 20 ms 크로스페이드로 넘어가 "딱" 소리가 나지 않습니다.
  - 호스트의 바이패스 버튼과 같은 기능이라 어느 쪽을 눌러도 함께 움직입니다.
  - 바이패스 중에는 스피커 배치 그림이 어두워지고 **BYPASS** 표시가 뜹니다. 이 표시를 **클릭하면 해제**됩니다(바이패스 중 스피커 클릭 테스트는 소리가 나지 않으므로 반응하지 않음).
- **업믹서 슬롯 (최대 4개)** — 아래 5-1

**아래** — 순차 테스트 톤 / 테스트 정지 · 현재 테스트 경로 · 모드 · 여유 버퍼 · 플러그인 지연(실제 값, 업믹서 포함) · 끊김 횟수(클릭하면 0으로) · 클럭 동기 상태

### 5-1. 업믹서 슬롯 (v1.2: 최대 4개)

호스트가 플러그인을 기본 채널 구성(스테레오 → 스테레오)으로만 여는 경우, "스테레오 입력 → 7.1.4 출력" 업믹서(예: **zAuro Pro 2D-3D Upmixer**)는 L/R만 출력합니다.
Atmos Bridge가 업믹서를 **직접 불러와 스테레오 → 7.1.4(12ch)로 열면** 이 문제가 없습니다.

1. 호스트 체인에는 **Atmos Bridge만** 둡니다(다른 업믹서는 빼거나 BYPASS).
2. 오른쪽 **+ 업믹서 추가** → 설치된 VST3 목록에서 업믹서를 고릅니다(목록에 없으면 "다른 위치에서 찾기…"). 추가한 업믹서는 바로 켜지고 설정 창이 열립니다.
3. 업믹서 **이름을 누르면** 설정 창이 다시 열립니다. zAuro라면 Speakers **7.1.4**, **Lb / Rb** 켜기.
4. 슬롯마다 열린 구성이 표시됩니다. 예: `Stereo → 7.1.4 Surround (12ch) · 지연 90.6 ms · 채널 순서 자동`
   - **채널 순서 자동**: 업믹서 출력이 채널 종류대로 L R C LFE SBL SBR SL SR TFL TFR TRL TRR에 맞춰 들어오므로 번호는 기본값(1~12) 그대로 두면 됩니다.
   - **번호 직접 지정**: 업믹서가 이름 없는 12채널로만 열린 경우입니다. 순차 테스트로 확인하며 번호를 맞추세요.

| 버튼 | 기능 |
|---|---|
| **O / X** | 켜기(O) / 끄기(X). 켜진 업믹서는 **하나뿐**이라, 다른 슬롯을 켜면 이전 슬롯은 꺼집니다. 모두 X면 호스트 채널 1~12를 그대로 씁니다 |
| **B** | 바이패스. 슬롯은 선택된 채로 업믹서만 거치지 않습니다(호스트 채널 그대로) |
| **D** | 삭제 |

- **번호표는 슬롯마다 따로 기억**합니다(업믹서 없음 상태도 따로). 예: zAuro는 1~12 기본값, zSonic은 다른 번호 — 슬롯을 바꾸면 번호표도 함께 바뀝니다.
- 업믹서 입력은 호스트 채널 **1~2**입니다.
- Atmos Bridge는 업믹서에 "스테레오 → 7.1.4", "스테레오 → 12ch", "7.1.4 → 7.1.4", "12ch → 12ch" 순서로 요청해 처음 받아들여진 구성을 씁니다. 모두 거절하면 이유가 표시됩니다.
- 각 업믹서의 설정은 Atmos Bridge 상태에 포함되어 호스트 프로젝트와 함께 저장됩니다. v1.1 프로젝트의 업믹서는 슬롯 1개로 자동으로 옮겨집니다.
- 꺼진 슬롯의 업믹서는 CPU를 쓰지 않습니다(켜진 슬롯 하나만 처리).

### 5-2. 테마 프리셋

상단 **테마** 메뉴에서 고릅니다: **Cyberpunk**(시안·마젠타, 초록 네온) · **White Modern**(흰 바탕, 노란 네온) · **Cool Beaches**(하늘·바다·모래, 파란 네온).
고른 테마는 프로젝트와 함께 저장되고, **이 PC의 사용자 설정**(`%APPDATA%\Atmos Bridge 7.1.4ch\AtmosBridge.settings`)에도 기록되어 플러그인을 새로 꽂거나 다른 프로젝트를 열어도 **마지막에 고른 테마**로 열립니다. 처음 한 번은 Cyberpunk로 시작합니다.

### 핑크 노이즈
- **-20 dBFS RMS 고정**. LFE는 **120 Hz 이하**로 제한된 노이즈입니다.
- 미리 생성해 둔 노이즈(4초 반복)를 재생하므로 실시간 계산 부담이 없습니다.
- 테스트 중에는 음악이 잠시 멈추고, 한 번에 한 곳만 나갑니다. AVR 볼륨을 평소보다 조금 낮추고 시작하세요.

### 모드

| 모드 | 입력 | 여유 버퍼 | 플러그인 지연(실제 값, 시뮬레이션 보통 PC / 바쁜 PC) | 용도 |
|---|---|---|---|---|
| 기본 | 호스트 | 100 ms | 약 130 ms | 음악 감상 (가장 안정적) |
| 저지연 (v1.4) | 직접 루프백 | 자동, 끊김 0 우선 (약 7 / 14 ms) | 약 37.5 / 44 ms | 영상·일반 감상 |
| 초저지연+ (v1.4) | 직접 루프백 | 자동, 타이밍 맞춤 (약 3 / 13 ms) | 약 34 / 40 ms, CABLE In 짧은 주기 적용 시 약 31 / 38 ms | 립싱크가 중요한 영상 |

- 직접 루프백을 쓸 수 없을 때는 호스트 입력으로 자동 전환됩니다: 저지연은 여유 8 ms(끊기면 10 ms씩 자동 증가, 최대 +60 ms — v1.3까지의 저지연과 같음), 초저지연+는 여유 4.5 ms(v1.2의 초저지연과 같음).
- v1.3의 "초저지연"은 v1.4의 **저지연**이 되었습니다(측정이 끝나면 바로 목표 여유로 가도록 개선). 예전에 "저지연"으로 저장한 프로젝트는 새 저지연, "초저지연"은 초저지연+로 열립니다.

- 하단의 "지연"은 입력 → 출력까지 **실제로 걸리는 시간**입니다. 업믹서가 켜져 있으면 그 지연이 더해집니다.

### 5-3. 저지연 · 초저지연+ = 직접 루프백 + 자동 보정 (v1.3~v1.4)

저지연과 초저지연+에서는 Atmos Bridge가 플레이어 소리를 **CABLE In 16ch에서 직접 받습니다**(WASAPI 루프백). 호스트가 소리를 받아 블록으로 넘기는 구간(호스트 내부 버퍼)이 없어져 그만큼 지연이 줄고, 지금 끊김의 주원인인 호스트 처리의 불규칙함도 없어집니다.

**세팅**: 상단 **저지연** 또는 **초저지연+**를 누르면 끝입니다. 하단 **입력** 칸이 "자동"이면 CABLE In 16ch를 스스로 찾습니다(다른 장치는 목록에서 선택, "호스트 (직접 루프백 끄기)"를 고르면 v1.2와 같은 방식). **호스트 설정은 바꾸지 않습니다** — Input: CABLE In 16ch [Loopback]은 비상용 경로입니다.

| 하단 상태 | 뜻 |
|---|---|
| 안정화 중 2:00 (노랑) | 처음 2분: 여유 15 ms로 이 PC의 흔들림을 잽니다 |
| 직접 루프백 동작 중 (초록) | 끊기지 않는 만큼으로 여유를 줄여 동작 중 |
| 직접 루프백 · 5 ms 주기 (초록) | 초저지연+: CABLE In 짧은 주기가 적용되어 루프백 패킷이 5 ms |
| 호스트 입력으로 대체 중 (노랑) | 문제가 있어 호스트 입력을 쓰는 중(마우스를 올리면 이유). 몇 초마다 다시 시도 |
| 호스트 입력 (기본) | 기본 모드는 호스트 입력 사용 |

**끊김을 막는 방법**
- 루프백 데이터마다 "언제 만들어졌는지" 시각으로 **얼마나 늦게 도착했는지**를 잽니다. 처음 2분은 여유 15 ms로 재기만 하고, 그 뒤 바로 목표 여유로 갑니다.
- **저지연**: **최근 10분 중 가장 늦었던 순간 + 1.5 ms**보다 여유를 줄이지 않습니다. 더 늦은 도착이 보이면 그 즉시 늘립니다.
- **초저지연+**: 늦은 패킷은 Atmos 출력이 데이터를 가져가는 순간보다 더 늦을 때만 문제가 됩니다. 패킷 도착과 출력 사이의 **타이밍 차이(위상)**를 계속 추적해, 가장 늦었던 순간 중 그 타이밍에서 실제로 필요한 만큼(+1 ms)만 여유를 둡니다. 두 장치의 시계가 천천히 어긋나는 방향을 1.5 ms 앞서 미리 반영합니다.
- 아슬아슬하게 늦은 패킷(여유 0.75 ms 미만)이 보이면 들리기 전에 여유를 1 ms 늘립니다. 늘린 여유는 10분 동안 유지합니다.
- 여유를 바꿀 때는 재생 속도를 **최대 0.3%**(크게 모자랄 때만 0.5%) 잠깐 바꿔서만 맞춥니다 — 무음을 끼우거나 소리를 건너뛰지 않습니다.
- 그래도 모자라면 무음 대신 **직전 10 ms를 거꾸로 이어붙이고 부드럽게 줄여** 감추고, 그만큼 여유를 늘립니다.
- 소리가 없을 때도 루프백이 멈추지 않도록 CABLE In 16ch에 **무음 스트림**을 흘립니다(재생 시작 때 첫소리 잘림 방지).

**CABLE In 짧은 주기 (초저지연+)**
- 무음 스트림이 Windows에 CABLE In의 처리 주기를 10 ms → **약 5 ms**로 요청합니다(IAudioClient3). 루프백 패킷이 짧아지면 지연이 약 3 ms 더 줄어듭니다.
- **VB-Cable(VB-Audio) 장치에는 요청하지 않습니다**(v1.4.1). VB-Cable은 요청을 받아들여도 패킷이 10 ms 그대로이고, 요청한 뒤 패킷 도착 간격만 불규칙해져 여유가 오히려 늘었습니다.
- 다른 장치는 직접 루프백을 쓰기 전에 **3초 동안 시험**합니다(그동안은 호스트 입력으로 재생). 패킷이 짧아지지 않으면 루프백과 무음 스트림을 **둘 다 기본 주기로 다시 열고**, 그 장치에는 호스트를 다시 열 때까지 다시 요청하지 않습니다.
- 드라이버가 짧은 주기를 지원하지 않거나 다른 앱이 이미 주기를 정해 두었으면 그대로 10 ms로 동작합니다.
- 적용 여부는 상태 표시("직접 루프백 · 5 ms 주기")와 툴팁("CABLE In 주기")에 나옵니다. 저지연에서는 요청하지 않습니다.

**자동으로 호스트 입력으로 돌아가는 경우**: 루프백 오류·장치 없음, 데이터가 0.3초 넘게 끊김, 샘플레이트가 호스트와 다름, 호스트는 소리를 받는데 루프백은 무음(플레이어가 독점 모드일 때). 전환 순간 한 번 짧게 소리가 튈 수 있습니다.

**알아 둘 점**
- 직접 루프백은 호스트를 거치기 전의 소리를 받으므로, 호스트 체인에서 **Atmos Bridge 앞에 둔 플러그인은 저지연·초저지연+에서 적용되지 않습니다**. 그런 플러그인을 쓸 때는 기본 모드를 쓰거나, 하단 입력을 "호스트 (직접 루프백 끄기)"로 고르세요(그러면 저지연 8 ms / 초저지연+ 4.5 ms 고정 여유로 호스트 입력을 씁니다).
- 업믹서 슬롯·번호표·뮤트·클리핑 방지·BYPASS는 그대로 동작합니다(업믹서 입력은 루프백 채널 1~2).
- Atmos 출력 장치(AVR)는 루프백 대상으로 고를 수 없습니다(피드백 방지).

- 플러그인 지연에는 Windows 공간 음향의 처리 단위(10 ms)와 입력 단위(호스트 블록 또는 루프백 패킷 5~10 ms) 하나가 항상 포함되므로 0이 될 수 없습니다.
- 출력 스레드와 루프백 스레드는 Windows **MMCSS "Pro Audio"** 작업에서 **최고(critical) 우선순위**로 동작하고, 실시간 버퍼는 **물리 메모리에 고정(VirtualLock)**하며, 오디오 처리 중에는 메모리 할당·잠금이 없습니다.
- Windows 인코딩 → HDMI → TV → AVR 디코딩·Dirac 구간의 지연은 고정이며 플러그인이 줄이거나 측정할 수 없습니다. 영상은 플레이어의 오디오 싱크 설정으로 맞추세요.
- 저지연·초저지연+에서 끊김이 생기면: Windows 전원 관리 "고성능", AMD 칩셋 드라이버 최신화, LatencyMon으로 드라이버 지연 점검.

## 6. 알아 둘 점

- Dolby 인코딩을 거치므로 원본과 비트 단위로 같지 않습니다(7.1.4 구성에서는 1:1에 가깝습니다).
- 재생 시작·정지 때 리시버가 Atmos ↔ PCM으로 바뀌며 앞부분이 살짝 잘릴 수 있습니다.
- 오프라인 렌더(파일로 내보내기) 중에는 HDMI로 출력하지 않습니다.
- 로그: `다운로드\AtmosBridge\Logs\atmosbridge.log` (문제가 있으면 증상과 함께 알려 주세요)

## 7. 소스에서 빌드

필요: Windows 10/11, Visual Studio 2022 이상(C++ 데스크톱 개발), CMake 3.22+, Git.

```bat
cmake -S . -B build -A x64
cmake --build build --config Release
```

결과물 (JUCE 8.0.15는 CMake가 자동으로 내려받습니다):
- `build\AtmosBridge_artefacts\Release\VST3\Atmos Bridge 7.1.4ch.vst3` (플러그인)
- `build\AtmosBridgeHost_artefacts\Release\Atmos Bridge Host.exe` (Host 앱)

DSP 단위 테스트: `g++ -std=c++17 -O2 -I Source tests/test_dsp.cpp -o test_dsp && ./test_dsp`

`main`에 push하면 GitHub Actions가 Windows에서 빌드하고, `CMakeLists.txt`의 버전으로 Release를 만들거나 갱신합니다.
